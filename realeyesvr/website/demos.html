What is being tested

This page separates measured progress from ideas still under investigation.

Current direction

Qwen first, validation after

Recent tests changed the pipeline. Qwen 3.5 now makes sense as the first visual gate, followed by deterministic processing and a targeted Claude review step.

Read the official Qwen 3.5 overview ↗

Validated direction

Direct visual analysis is the initial gate

The earlier approach began with local signal processing to find table regions. Recent results indicate that Qwen can understand the full sheet well enough to lead the process. Traditional detection remains useful as a fallback and independent check.

Current benchmark target

Door and frame schedules

Testing began with sheet A8.2 and focuses on door rows, dimensions, materials, hardware groups, frame types, ratings, and remarks. Merged cells and hardware-group blocks remain important stress cases.

Evaluation principle

“Almost 100%” needs a precise definition

Table detection, row count, field extraction, normalized values, and final reviewed records are separate measures. The next benchmark should report each one so improvements remain meaningful.

Long-term asset

The schema and verified dataset matter most

Models will change. A collection of hand-verified construction schedules, paired with clear schemas and source evidence, makes future models easier to compare and replace.

Roadmap

The next useful milestones

Small, measurable steps before broad automation.

Now

Repeatable single-sheet extraction

Document the exact model, prompt, settings, output, review, and score.

Next

Source-linked validation

Connect every extracted field to its sheet region and review state.

Then

Drawing-set routing

Use the drawing index to route likely schedule sheets to the right schema.

Later

Cross-source reconciliation

Compare schedules, specifications, BIM records, and drawing revisions.

Planned working example

The RealEyesVR Test Lab

In development

The Test Lab will let authenticated Hugging Face users try one focused version of the pipeline themselves. Shared ZeroGPU infrastructure supplies the temporary GPU; the user only needs a browser and a safe test image.

01

Sign in

Use a Hugging Face account so RealEyesVR does not store passwords.

02

Upload safely

Submit one public, synthetic, or otherwise authorized schedule image.

03

Run Qwen

ZeroGPU temporarily allocates shared GPU capacity for extraction.

04

Check the result

Review structured rows, validation warnings, source evidence, and raw JSON.

First test case

Door and frame schedules

One image, one known schema, and one measurable result. Broader drawing types come only after this workflow proves repeatable.

What it will measure

Real-world behavior

Processing time, row count, field accuracy, validation warnings, corrections, and whether the result was useful without expert guidance.

Privacy boundary

No confidential drawings

The Test Lab will use cloud processing. Visitors must not upload client, employer, personal, or otherwise restricted information.

Follow the prototype

Built in public, tested carefully.

The first release will favor a small, understandable experiment over a broad claim of construction-document automation.
