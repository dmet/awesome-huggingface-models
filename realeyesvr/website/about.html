Why this project exists

Built from inside construction

RealEyesVR began with a practical VDC/BIM question: why does so much useful project information remain locked inside documents?

The perspective

This is a construction problem before it is an AI problem.

Drawing schedules are created carefully, reviewed repeatedly, and used across the life of a project. Yet their contents are rarely transferred into a durable, queryable data layer.

RealEyesVR is an independent personal research project informed by hands-on VDC and BIM experience. It explores a straightforward idea: modern visual models can help read construction documents, while domain rules and human review can make the resulting information dependable.

The aim is not to replace construction judgment. It is to reduce repetitive data entry, make document information easier to verify, and give teams a stronger foundation for decisions.

“If a result cannot be traced back to the drawing, it does not belong in the data twin.”

Focus

Construction drawing schedules and structured project data

Current model

Qwen 3.5 as the first visual gate

Review approach

Deterministic validation plus targeted model and human review

Starting domain

Doors, frames, and hardware groups

Long-term goal

A source-linked construction data twin

Guiding principles

Benchmark first

Decisions should follow repeatable tests on verified drawing data.

Keep the evidence

Sheet, revision, and location remain attached to every value.

Use the right tool

AI handles visual interpretation; ordinary code handles deterministic checks.

Be clear about uncertainty

Unknown is a valid result. Guessing is not.
